### Task 4: Guía RTL-SDR (drivers, prueba, autenticidad)

**Files:**
- Modify: `docs/setup/rtl-sdr.md`

**Step 1: Escribir la guía.** Estructura y hechos exactos:

1. Frontmatter: `title: "Configurar el RTL-SDR"`, `description: "Drivers, prueba con rtl_test y verificación de autenticidad del RTL-SDR Blog V3/V4 en Windows, Linux y macOS."`
2. Admonition `!!! info "Opcional"`: el dongle no es obligatorio. Prerrequisito: radioconda instalado (Tarea 3).
3. `## Datos del hardware`: RTL2832U + tuner R828D (V4) o R820T2 (V3). USB 2.0 (no requiere USB 3.0). 8 bits I/Q. Tasa estable máxima 2.4 MS/s (2.56 con pérdidas ocasionales). Rango 24 MHz–1.766 GHz; V4 además 500 kHz–24 MHz vía upconverter integrado. Bias-tee 4.5 V (V3/V4) para LNA. Antena del kit: dipolo telescópico ajustable.
4. `## Driver` con pestañas:
   - **Windows** (Zadig):
     1. Conectar el dongle. Windows instala un driver de TV (DVB-T) que hay que reemplazar.
     2. Descargar Zadig de https://zadig.akeo.ie/ (ejecutable único, no requiere instalación).
     3. Ejecutar Zadig como administrador → menú `Options → List All Devices`.
     4. En el desplegable elegir **`Bulk-In, Interface (Interface 0)`** (V4 y V3 lo muestran así). Si aparece `RTL2832UHIDIR` o `RTL2838UHIDIR`, también sirve. **No** elegir `Interface 1`.
     5. A la derecha del botón debe decir **WinUSB** (no libusb-win32, no libusbK). Pulsar `Replace Driver` (o `Install Driver`).
     6. Cerrar Zadig. Si Windows 11 rechaza instalar el driver: Configuración → Privacidad y seguridad → Seguridad de Windows → Seguridad del dispositivo → Aislamiento del núcleo → desactivar "Integridad de memoria", reiniciar, repetir Zadig. Después se puede reactivar (WinUSB es compatible).
     7. Admonition `!!! warning "Windows Update puede devolver el driver de TV"`: si el dongle deja de funcionar tras una actualización, repetir Zadig. Para evitarlo, crear un archivo `no-driver-updates.reg` con el contenido de abajo y ejecutarlo (doble clic). Aviso: desactiva la búsqueda de drivers en Windows Update **para todos los dispositivos**; revertible con el segundo archivo.

     ```
     Windows Registry Editor Version 5.00

     [HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\PolicyManager\current\device\Update]
     "ExcludeWUDriversInQualityUpdate"=dword:00000001

     [HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\PolicyManager\default\Update]
     "ExcludeWUDriversInQualityUpdate"=dword:00000001

     [HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\WindowsUpdate\UX\Settings]
     "ExcludeWUDriversInQualityUpdate"=dword:00000001

     [HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate]
     "ExcludeWUDriversInQualityUpdate"=dword:00000001

     [HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\PolicyManager\default\Update\ExcludeWUDriversInQualityUpdate]
     "value"=dword:00000001

     [HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Device Metadata]
     "PreventDeviceMetadataFromNetwork"=dword:00000001

     [HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\DriverSearching]
     "SearchOrderConfig"=dword:00000000
     "DontSearchWindowsUpdate"=dword:00000001
     ```

     Revertir (`driver-updates-on.reg`):

     ```
     Windows Registry Editor Version 5.00

     [HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\PolicyManager\current\device\Update]
     "ExcludeWUDriversInQualityUpdate"=-

     [HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\PolicyManager\default\Update]
     "ExcludeWUDriversInQualityUpdate"=-

     [HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\WindowsUpdate\UX\Settings]
     "ExcludeWUDriversInQualityUpdate"=-

     [HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate]
     "ExcludeWUDriversInQualityUpdate"=-

     [HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\DriverSearching]
     "SearchOrderConfig"=dword:00000001
     "DontSearchWindowsUpdate"=-
     ```

     Fuente: https://www.rtl-sdr.com/a-registry-hack-to-stop-windows-11-replacing-the-winusb-driver-installed-via-zadig/
   - **Linux** (con radioconda activado, `$CONDA_PREFIX` definido):

     ```bash
     sudo ln -s $CONDA_PREFIX/etc/modprobe.d/rtl-sdr-blacklist.conf /etc/modprobe.d/radioconda-rtl-sdr-blacklist.conf
     sudo modprobe -r $(cat $CONDA_PREFIX/etc/modprobe.d/rtl-sdr-blacklist.conf | sed -n -e 's/^blacklist //p')
     sudo ln -s $CONDA_PREFIX/lib/udev/rules.d/rtl-sdr.rules /etc/udev/rules.d/radioconda-rtl-sdr.rules
     sudo udevadm control --reload
     sudo udevadm trigger
     ```

     Desconectar y volver a conectar el dongle. Fuente: README de radioconda, sección RTL-SDR.
   - **macOS**: no requiere driver. Conectar y pasar a la prueba.
5. `## Prueba 1: detección`. Comando: `rtl_test -t`. Salida esperada (V4):

   ```
   Found 1 device(s):
     0:  RTLSDRBlog, Blog V4, SN: 00000001

   Using device 0: Generic RTL2832U OEM
   Found Rafael Micro R828D tuner
   RTL-SDR Blog V4 Detected
   Supported gain values (29): 0.0 0.9 1.4 2.7 3.7 7.7 8.7 12.5 14.4 15.7 16.6 19.7 20.7 22.9 25.4 28.0 29.7 32.8 33.8 36.4 37.2 38.6 40.2 42.1 43.4 43.9 44.5 48.0 49.6
   ```

   V3: `Found Rafael Micro R820T tuner` y sin la línea "V4 Detected". Si dice `usb_claim_interface error -6` (Linux): el módulo DVB sigue cargado, repetir el paso de blacklist. Si `No supported devices found` (Windows): Zadig no se aplicó a la interfaz correcta.
6. `## Prueba 2: pérdida de muestras`. Comando: `rtl_test -s 2400000` durante 60 s (Ctrl+C para parar). Salida esperada: líneas `Reading samples in async mode...` y **ninguna** línea `lost at least N bytes`. Con pérdidas ocasionales (< 5 en 60 s) es aceptable. Con pérdidas continuas: cambiar de puerto USB (evitar hubs y adaptadores USB-C baratos), cerrar programas pesados, probar `-s 2048000`. Guardar la salida en un archivo de texto: forma parte del Reporte 0.
7. `## Prueba 3: primer espectro en GRC`. Abrir `prueba.grc` de la guía anterior; reemplazar `Signal Source` + `Throttle` por `RTL-SDR Source` (módulo osmocom): `Sample Rate` 2.4e6, `Ch0: Frequency` 99.1e6 (o cualquier emisora FM local), `Ch0: RF Gain` 30. `samp_rate` = 2.4e6. Ejecutar: se ven las portadoras FM de ~200 kHz de ancho. Captura para el Reporte 0.
8. `## Autenticidad y clones`. Señales de clon: `rtl_test` no imprime "RTL-SDR Blog V4 Detected" en un dongle vendido como V4; tuner `FC0012`/`FC0013`/`E4000` en vez de R828D/R820T; sin bias-tee; carcasa sin marca. Fuente: https://www.rtl-sdr.com/genuine/
9. `## Grabar muestras IQ` (para labs y proyecto):

   ```bash
   rtl_sdr -f 99.1e6 -s 2400000 -g 30 -n 24000000 fm_99p1MHz_2p4Msps_g30.cu8
   ```

   `-n` = número de muestras (24 M = 10 s a 2.4 MS/s = 48 MB). Formato: bytes sin signo intercalados I,Q (uint8), offset 127.5. Nombre: `<señal>_<fc>_<fs>_g<ganancia>.cu8`. Para leerlo en NumPy:

   ```python
   import numpy as np
   raw = np.fromfile("fm_99p1MHz_2p4Msps_g30.cu8", dtype=np.uint8)
   iq = (raw[0::2].astype(np.float32) - 127.5) / 127.5 + 1j * (raw[1::2].astype(np.float32) - 127.5) / 127.5
   ```

   En GRC: `File Source` (tipo byte) → `UChar To Float` … o más simple: `File Source` con tipo `complex` **no** sirve para `.cu8`; usar el bloque `osmocom Source` con `file=<ruta>,rate=2.4e6` o convertir a complex64 una vez con NumPy (`iq.astype(np.complex64).tofile("archivo.cfile")`) y leer el `.cfile` con `File Source` tipo complex + `Throttle`. Documentar las dos opciones.
